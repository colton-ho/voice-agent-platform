## 四、两个开发解释点（agree/disagree + 理由）

**(a) `VOICE_ENGINE=cascade` → `create()` returns a plain `(stt, llm, tts)` tuple composed via the three kinds' factories — AGREE.**
§3.4 freezes "composition root composes FC-2 + FC-3 + FC-4"; `providers/registry.py:96-103` implements exactly that: the cascade branch recursively resolves `STT`/`LLM`/`TTS` through their own explicit selections and returns the bare tuple. Fabricating an adapter object would be worse in both directions: it would masquerade as an FC-5 `RealtimeVoiceEngine` (it is not one) and would violate spec §5's "avoid broad interface abstractions that force incompatible provider behaviour into misleading single method". Tests prove each factory is called exactly once and composition is all-or-nothing (`tests/test_provider_registry.py:196-222`). Carried caveat (F-07): `create` returns a union type — acceptable because the composition root is the sole consumer, but annotate it.

**(b) Legacy denylist = `bedrock / aws_transcribe / polly / nova-sonic / transcribe / minimax`, banned at register AND resolve — AGREE (as frozen).**
The four §3.4-named AWS providers plus `transcribe` (bare legacy alias of the `AWSTranscribeSTTService` selection) and `minimax` (legacy `SimpleMiniMaxTTSService` path — non-AWS, but precisely the "unapproved external provider" spec §11 forbids silently falling back to; its env-coupled `MINIMAX_API_KEY` era is dead code to be replaced by an adapter under a **new** name after G-1/G-2, per the comment at `providers/registry.py:70`). Dual-layer enforcement with never-fall-back proof (`tests/test_provider_registry.py:166-190`) and "lifting needs a CR" is consistent with CR-2's fail-loud posture. Endorse for Phase B.
