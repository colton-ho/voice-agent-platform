# Requirements — Azure Voicebot Migration (Phase 1 Deliverable)

Author: 许清楚 (req-analyst) · Status: draft for review · Source spec: `docs/Azure_Voicebot_Implementation_Instructions_Corrected.md` (v2.0, 6 Nov 2026)
Repository evidence verified 2026-06-10 against `/Users/colton/Developer/voice-agent-platform`. Items marked "unverified" were not observable in the repository.

## 1. Purpose and scope

Rebuild the existing Pipecat-based voicebot so it runs on Azure without any AWS runtime dependency, preserving every existing business workflow — inbound PSTN and web voice conversations in Cantonese, Mandarin, English, and Japanese; scenario presets including KB-grounded `acme-security-support`; agent tools (`end_call`, `transfer_to_human`, MCP/REST tools); call history, summaries, web monitoring, admin console, and the human-handoff workflow — while replacing the hosting, speech, LLM, persistence, secrets, async, observability, and CI/CD substrate with the Azure baseline of spec §2 (Container Apps, Twilio bidirectional Media Streams, Azure Speech STT → approved LLM → Azure Speech TTS, Cosmos DB, Blob, Key Vault, Service Bus, Azure Monitor/OTel, managed identity, Bicep, GitHub Actions OIDC). Delivery is staged per spec §14 Phase A–E; production cutover is gated on the approval items in §4 and the blocking decisions in §5 of this document. This document states *what* must be true; it does not design interfaces or choose technologies beyond the spec's mandated baseline.
